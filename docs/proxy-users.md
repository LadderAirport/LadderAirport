# 用户与协议准入

给每个人分配独立的协议凭据（UUID / 密码），不提供登录入口：用户拿到的只有订阅链接。停用用户后，其订阅链接和节点访问会同时失效。

## 概念

| 对象 | 作用 |
|------|------|
| 用户 | 名称、备注、启用开关，以及一个随机密钥。该用户所有协议的凭据都由这个密钥派生 |
| 订阅的「绑定用户」 | 绑定后，订阅里的本地节点和代理链各跳改用该用户的凭据；不绑定则沿用入站的共享凭据 |
| 节点的「仅准入用户」 | 开启后，该节点上入站的共享凭据失效，只接受已绑定用户的凭据 |

一个用户可以绑定多个订阅，比如 Clash 一份、手机一份，各自选择不同的节点。

「仅准入用户」按节点设置：同一个入站关联到多个节点时，可以在香港节点上只准入用户，在家里的节点上继续用共享凭据。

## 准入范围

用户能访问哪些入站，由其**有效订阅**决定：订阅已启用、未停用，且用户已启用。

- 订阅勾选的本地入站（「全部本地入站」即所有入站）。
- 订阅包含的已启用代理链的每一跳。

节点配置里每个入站的 `users` 列表按上面的规则生成，sing-box 用户名是用户 ID。订阅范围之外的入站不会写入该用户的凭据，所以手动拼出来的配置也连不上。

## 协议支持

| 协议 | 每个用户的凭据 |
|------|------|
| VLESS（含 Reality） | uuid，flow 跟随入站设置 |
| VMess | uuid |
| Trojan / Hysteria2 / AnyTLS | password |
| TUIC | uuid + password |
| HTTP / SOCKS5 / Auto | username（用户 ID）+ password；入站必须开启认证 |
| Shadowsocks | 只支持 `2022-blake3-aes-128-gcm` / `2022-blake3-aes-256-gcm`，且只在所在节点开启「仅准入用户」后生效 |

其他情况（传统 SS 加密、`2022-blake3-chacha20-poly1305`、未开启认证的 HTTP / SOCKS）不能区分用户。这类入站在用户订阅里仍使用共享凭据；**节点开启「仅准入用户」后，它们也继续使用共享凭据**，任何拿到共享凭据的人都能用。「用户」页的节点准入列表会把这类入站列出来。要彻底收紧，就把它们改成支持的协议，或者从该节点上取消关联。

### Shadowsocks 2022 的特殊处理

SS2022 的多用户模式要求客户端密码写成 `服务端密钥:用户密钥`，开启后，只带服务端密钥的旧客户端会连不上。所以 SS 入站在共享模式下保持单用户，用户订阅里也用共享密码。所在节点开启「仅准入用户」时才切换到多用户模式，客户端需要刷新订阅。

## 共享模式与仅准入模式

下表说的是能区分用户的入站在该节点上的行为：

| | 共享模式（默认） | 仅准入用户 |
|---|---|---|
| 入站的共享凭据 | 可用 | 失效 |
| 用户订阅 | 用户自己的凭据 | 用户自己的凭据 |
| 未绑定用户的订阅 | 正常包含该入站 | 不再包含该节点上的这个入站；经过它的代理链整条省略 |

建议的迁移步骤：先建用户、给订阅绑定用户，等大家都刷新过订阅后，再逐个节点开启「仅准入用户」。

开启「仅准入用户」后，Panel 还会给这个节点保留一个内部凭据（sing-box 用户名 `__panel`），供全局路由计划在节点上组合代理链时使用。这个凭据不会出现在任何订阅里。

### 从 v0.17.0 升级

v0.17.0 的「仅准入用户」是按入站设置的。升级后会自动迁移：凡是关联过（作为独立入站或代理链跳点）开启了仅准入的入站的节点，都会开启「仅准入用户」。宁可收紧也不放开，迁移后不再保留按入站的开关。迁移前后请到「用户」页核对节点准入列表。

## 生效方式

以下操作会在最后一次变更约 5 秒后，自动给所有节点重新下发配置：
- 停用、启用、删除用户，重置凭据；
- 订阅绑定或解绑用户、修改绑定了用户的订阅，以及启用、停用、删除这类订阅；
- 节点开启或关闭「仅准入用户」；
- 存在绑定用户的订阅时，修改、启用、停用、删除代理链。

配置没有变化的节点不会重启。**配置有变化的节点会整体重启 sing-box，节点上所有连接都会短暂中断。** uplink 节点要等下一次拉取配置才生效。

## 重置凭据

订阅令牌和凭据是两回事：
- **轮换订阅令牌**：只让旧链接失效，已经下发到客户端的凭据仍然可用。
- **重置凭据**：更换用户密钥，该用户所有派生的 UUID / 密码都会变。客户端必须刷新订阅。

怀疑凭据泄露时，两者都做一遍。
