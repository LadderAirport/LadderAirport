# Panel 前端工程约定

本文原为 2026-07 一轮前端优化的方案与修复记录。该轮修复（路由懒加载、统一 401 处理、请求代次防过期、表单契约对齐、响应式与可访问性补齐等）已全部落地，现精简为长期有效的现状描述与工程约定；历史修复明细与 P0–P3 路线图不再保留。

**范围：** `web/` React 前端、与前端契约直接相关的 Panel API，以及 `panel/web/dist` 嵌入产物。

## 信息架构

认证后主导航八个入口（`web/src/App.tsx`）：

| 导航 | 路由 | 核心任务 |
|------|------|----------|
| 节点 | `/` | 机群状态、筛选、批量操作、节点详情 |
| 入站 | `/inbounds` | 协议入站的创建、编辑、校验与启停 |
| 代理链 | `/chains` | 多跳代理链编排（客户端组合） |
| 路由计划 | `/route-plans` | 全局/订阅级分流规则 |
| 订阅 | `/subscriptions` | 订阅组合、外部源、预览与链接 |
| 证书 | `/pki` | 管理面 mTLS 证书台账与吊销 |
| DNS/ACME | `/dns-certificates` | DNS 账号、托管域名、协议证书、自动化任务 |
| 设置 | `/settings` | 刷新、探测、升级与安全配置 |

路由规则：

- 未认证访问业务路由跳转 `/login?next=<原路径>`，登录后返回原位置；全局 401 只触发一次会话失效流程。
- 节点详情是 `/?node=<id>` 驱动的侧边抽屉：保留列表上下文，可刷新和分享深链；关闭抽屉只移除该参数。无效深链必须显示明确错误和关闭/重试操作。
- 未知路径回到节点页；页面标题随当前导航更新。

## 交互与可靠性约定

状态必须具体，不用一个 `loading` 表示整页所有动作：

- 首次加载用稳定占位；后台刷新保留已有内容；单项提交只锁定对应行或按钮。
- 批量任务显示总进度和逐节点结果，部分成功不等同于全部失败。
- 空数据解释原因并给出相关入口；失败区域保留错误和重试动作。
- 未获取到的数据用 `—`，真实数值为零时才显示 `0`；`pending`/`unknown` 不得误判为离线。

跨越组件生命周期的请求遵循同一规则：

1. 发起请求时捕获资源 ID 和递增代次。
2. 响应写入前确认组件仍挂载、资源 ID 未变化且代次最新。
3. 新请求、切换资源或卸载时中止可取消请求（含日志流）。
4. 错误转换集中在 API 客户端（统一解析 JSON/文本错误体），页面只决定展示位置。

操作必须可预期：

- 提交未完成前按钮不可重复触发；删除、覆盖敏感配置、放弃未保存修改需确认。
- 设置页分离草稿与已保存状态，有脏数据提示和放弃确认；保存失败保留草稿。
- Token、密码等敏感字段默认遮蔽，仅在用户明确修改时发送；复制与显隐是显式动作。
- 中文术语保持统一：节点、入站、代理链、路由计划、订阅、外部源、下发、探测、部分成功。

## 表单与 API 契约

- 创建和更新输入类型分离；更新请求只发送用户实际编辑的字段（Node 局部更新）。
- 需要区分「未提交」和零值的字段在后端使用指针语义（如 Inbound `enabled`）。
- 客户端校验覆盖必填、端口范围、URL、JSON、重复标签和字段间依赖；服务端执行最终校验。
- 协议动态表单由模板 schema 驱动，字段标签、帮助和错误必须关联到具体控件。
- 订阅用 `include_all_inbounds` 明确区分「全部本地入站」和「未选择本地入站」。

## 性能预算

- 路由级代码拆分：所有页面动态加载；任一路由 chunk 原始大小不超过 500 KiB。
- 入口 JS gzip 建议不超过 250 KiB；超限需在变更说明中给出原因（预算门禁待加入 CI）。
- 轮询未结束不启动下一轮；手动刷新与自动刷新不并发覆盖。
- 任一列表超过 500 行或交互明显掉帧时，引入服务端分页或虚拟列表。

## 可访问性与响应式基线

- 主导航、主内容、标题层级和跳转主内容链接语义完整；图标按钮必须有 `aria-label`，字段有可见标签，错误通过 `aria-describedby` 关联。
- 所有核心流程仅用键盘（Tab / Shift+Tab / Enter / Space / Escape）可完成；浮层打开焦点进入、关闭回到触发元素。
- 状态不能只依赖颜色；正文、边框和焦点环满足 WCAG 2.1 AA。
- 响应式验收视口至少包括 `1440×900`、`1024×768`、`768×1024`、`390×844`、`320×568`：无页面级横向滚动、文字不截断、浮层不越界、表格可滚动、固定区域不遮挡最后一项。

## 安全与隐私

- 生产环境使用 HTTPS；HTTP 剪贴板回退只解决兼容性，不替代传输安全。
- 不把 Token、密码、请求头或 CA 私钥放入 URL、日志、错误堆栈和持久化视图状态。
- 退出登录调用服务端注销并清理客户端认证状态。
- 用户粘贴的请求头 JSON 只解析为结构化数据，不做动态执行或 HTML 注入。
- 错误边界展示可恢复说明，详细错误仅写入开发者控制台。

## 测试与发布门禁

本地验证顺序：

```bash
cd web
npm ci
npm run typecheck
npm test
npm run build

cd ../panel && go test ./...
cd ../pkg && go test ./...
cd ../agent && go test -tags with_quic,with_utls ./... -timeout 120s
```

`npm run build` 已包含类型检查；单独执行 `npm run typecheck` 是为了更快定位类型错误。CI 必须使用 `npm ci`。

内嵌静态资源一致性：Panel 构建使用提交在 `panel/web/dist` 中的前端产物。每次修改 `web/src` 后必须重新构建并同步，然后执行：

```bash
diff -qr web/dist panel/web/dist
```

任何差异都应阻断合并，防止源码已修复但发布二进制仍携带旧界面。

CI 合并条件：

- `npm test`、`npm run build` 全部通过，无 TypeScript 错误。
- `web/dist` 与 `panel/web/dist` 完全一致。
- `panel`、`pkg`、带 `with_quic,with_utls` 标签的 `agent` 测试通过。
- 新增 API 字段同时具备存储迁移、旧数据兼容和 handler 回归测试。
- P0/P1 前端缺陷修复必须附对应自动化测试；暂时无法自动化时，在变更说明中记录手工步骤和结果。

现有测试分层：类型检查（`tsc -b`）、纯函数单元测试（Node Test，`web/tests/*.test.mjs`）、Go 侧 API/存储契约测试。组件测试（Vitest + Testing Library）和端到端冒烟（Playwright 桌面/移动矩阵）尚未引入，是高风险交互重构前的优先事项。

## 完成定义

一次 Panel 前端改动只有同时满足以下条件才算完成：

1. 正常、加载、空数据、错误和处理中状态均有明确界面。
2. 快速重复操作、页面切换和慢网络不会产生过期数据或重复提交。
3. 桌面和移动端核心流程可完成，键盘可到达所有必要操作。
4. 类型检查、前端测试、生产构建和相关 Go 测试通过。
5. `web/dist` 与 `panel/web/dist` 已同步并由 CI 校验。
6. 用户可见行为变化有测试或可复现的手工验收记录。
