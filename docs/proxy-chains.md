# 代理链

代理链把 2–8 个节点入站按顺序串起来：客户端先连第 1 跳，再经第 1 跳连第 2 跳，依此类推，最后一跳是公网出口。

链路**在客户端配置里组合**，不在服务端中转。节点只运行自己的普通入站，出站一律 `direct`。

## 跳点

- 每一跳是一个**已关联到节点的入站**（「Agent 管理 → 入站关联」里的独立绑定）。先关联入站，才能把它选作跳点。
- 多条链可以共用同一个绑定，比如都从同一个入口进。同一条链里一个节点只能出现一次。
- 节点、入站或绑定被链引用时受保护：不能删除节点，不能删除入站，不能取消关联；被已启用的链引用时，也不能禁用入站。修改入站的协议和参数不受限制，客户端刷新订阅后生效。

每一跳的地址按下面的顺序取第一个非空值：

| 字段 | 优先级 |
|------|--------|
| 地址 | 跳点 `dial_address` → FRP 服务器 → 托管 TLS 域名 → 绑定 `public_address` → 节点 `public_address` → 节点 `address` |
| 端口 | 跳点 `dial_port` → FRP 远端端口 → 绑定 `public_port` → 节点端口映射后的监听端口 |

第 1 跳的地址由客户端拨号，其余各跳的地址由**上一跳所在的节点**拨号。所以中间跳可以填内网地址，例如两台机器之间的专线 IP。

## 订阅输出

订阅勾选「代理链」（或「全部已启用链」）后，每条已启用的链会按格式渲染：

| 格式 | 组合方式 |
|------|----------|
| Clash / Mihomo | 第 N 跳的代理带 `dialer-proxy: <第 N−1 跳>` |
| sing-box | 第 N 跳的出站带 `detour: <第 N−1 跳>` |
| V2Ray 分享链接 | 无法表达链路，省略代理链 |

- 出口那一跳用链名，归入「链式代理」组，也是唯一可选的一项。中间跳命名为 `<链名>-跳N`，只供下一跳引用，不出现在选择组 / selector 里。
- 代理链在去重和改名**之后**追加，所以与独立入站同地址的跳点不会被合并掉。
- 跳点协议要能承载下一跳的流量。比如下一跳是 Hysteria2 / TUIC（UDP），上一跳必须支持 UDP 转发。

## 启用与停用

启用、停用和修改链路都只改数据，不向节点下发配置。客户端刷新订阅后生效。

例外：被已启用的**全局路由计划**引用时，链的变化会触发一次全量节点下发（见下）。

## 全局路由计划

全局计划的 `proxy` 规则把匹配的流量送进目标链。节点在本机用 `detour` 组合这条链：

- 节点不在链上：从第 1 跳开始组合整条链。
- 节点是第 k 跳：从第 k+1 跳开始组合。
- 节点是出口：规则落到 `direct`。

只有第一个组合出站直接拨号，所以只有它带 `bind_interface` 和 `domain_resolver`。后续各跳经 `detour` 拨出，主机名交给上游解析。详见 [路由计划](route-plans.md)。

## 从服务端中转升级

旧版本由 Panel 给每一跳下发「链专用入站 + 指向下一跳的出站」，并定时探测整条链。升级后首次启动会一次性迁移：

- 旧的链专用入站自动变成对应节点的独立绑定，原来写在入站模板上的 FRP 设置移到绑定上。
- 取消「同一绑定只能属于一条链」的限制。
- 链路探测、部署状态和探测设置（`chain_probe_*`）一并移除。

迁移后各节点下一次下发时只剩普通入站，原来的链出站和按入站路由的规则会消失。使用这些链的客户端需要刷新订阅，改由客户端组合链路。
